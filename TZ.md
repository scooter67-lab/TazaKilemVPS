Ты — senior full-stack разработчик. Нужно разработать полноценное веб-приложение “Журнал ковромойки”.

Стек:
- Frontend: React (Vite), TypeScript
- Backend: FastAPI (Python)
- База данных: PostgreSQL
- ORM: SQLAlchemy
- Аутентификация: JWT (access + refresh токены)
- UI: простой, без перегруза (можно использовать базовые компоненты)

Общие требования:
- Код должен быть готов к запуску
- Чистая архитектура (разделение frontend/backend)
- Понятная структура файлов
- Минимум лишней сложности, но с заделом на масштабирование

=====================
ФУНКЦИОНАЛ
=====================

РОЛИ:
- Admin
- User

АВТОРИЗАЦИЯ:
- Логин/пароль
- JWT авторизация
- Хеширование паролей
- Middleware для проверки ролей
- Возможность иметь несколько админов
- Админ может управлять ролями пользователей

СМЕНЫ:
- У пользователя может быть только 1 активная смена
- Смена:
  - id
  - user_id
  - дата открытия
  - дата закрытия
  - статус (active / closed)
- После закрытия смены:
  - редактирование запрещено для пользователя
  - доступно только админу

ЗАЯВКИ:
- Внутри смены пользователь создает заявки
- У заявки:
  - id (уникальный)
  - shift_id
  - номер заявки (вводится вручную)
- Пользователь может:
  - создавать несколько заявок
  - переключаться между ними
  - редактировать, пока смена открыта

КОВРЫ:
- Внутри заявки неограниченное количество ковров
- У ковра:
  - id
  - request_id
  - длина
  - ширина
  - квадратура (расчет: length * width)
- Автоматический расчет:
  - квадратура ковра
  - сумма по заявке
  - сумма по смене

ЗАКРЫТИЕ СМЕНЫ:
- Перед закрытием:
  показать подтверждение:
  “Вы уверены? После закрытия редактирование невозможно”
- После закрытия:
  смена становится журналом

ЖУРНАЛ:
- Это закрытая смена
- Содержит:
  - сотрудника
  - дату
  - заявки
  - ковры
  - квадратуру
  - итог
- Пользователь не может редактировать
- Админ может редактировать

АДМИНКА:
- Управление пользователями
- Назначение ролей
- Просмотр всех смен
- Редактирование журналов
- Просмотр статистики:
  - по сотрудникам
  - по квадратуре
  - по заявкам

=====================
БАЗА ДАННЫХ
=====================

Нужно создать модели:
- User (id, username, password_hash, role)
- Role (id, name)
- Shift (id, user_id, opened_at, closed_at, status)
- Request (id, shift_id, request_number)
- Carpet (id, request_id, length, width, area)

Добавить связи:
- User → Shift (1:M)
- Shift → Request (1:M)
- Request → Carpet (1:M)

=====================
API (FastAPI)
=====================

Реализовать эндпоинты:

Auth:
- POST /login
- POST /refresh

Users:
- GET /users (admin)
- POST /users (admin)
- PATCH /users/{id} (admin)

Shifts:
- POST /shifts/open
- POST /shifts/close
- GET /shifts/current
- GET /shifts (admin)

Requests:
- POST /requests
- GET /requests/{shift_id}
- PATCH /requests/{id}

Carpets:
- POST /carpets
- PATCH /carpets/{id}
- DELETE /carpets/{id}

Journal:
- GET /journals
- PATCH /journals/{id} (admin only)
